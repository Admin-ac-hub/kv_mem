# 固定三节点安全切换

用户已确认：三个固定节点，安全优先，完成后做足够但不过度的测试。

- 新增可选的 `kv_cluster_server` / `kv_cluster_client`，不改变原有单节点服务；复用 miniRPC 帧、服务端与 KV 引擎。
- 固定成员 1/2/3，显式 cluster ID 和六个地址（三个业务、三个节点间 RPC）。同机三进程默认，可配置不同 IPv4 主机。配置与节点身份持久化，不允许用同一目录更换身份或成员。
- 实现 Raft 随机选举、持久化任期/投票、日志匹配与冲突回退。只有当前任期日志获得多数派持久化确认才提交，提交后顺序应用 KV。业务和节点间服务使用独立线程池。
- 所有成功读取也通过当前任期的多数派日志屏障，不使用依赖时钟的 lease。失去多数派拒绝成功读写。客户端先发现 Leader，明确未接收的请求可换节点；未知写入结果不自动重试。
- 持久状态用带长度和 CRC 的完整文件：写临时文件、fsync、rename、fsync 目录；任何持久化/应用错误进入 fail-stop。节点独占目录锁。损坏或配置不匹配拒绝启动，不静默清空。
- commit index 先持久化再应用。重启按顺序重放全部已提交日志，Put/Delete 的重放幂等；不把 KV 序号当作 Raft index，不依赖易崩溃的单独 applied marker。
- 第一版保留所有日志，每次持久化重写状态，读取也追加屏障。明确 O(历史日志大小) 开销和有限容量，不做动态成员、快照压缩、分片、TLS、鉴权或 exactly-once。部署于受信网络。
- 测试：现有回归一次；定向检查投票恢复、日志冲突/旧主隔离、持久状态损坏与故障点；真实三进程 TCP 测试覆盖强杀主节点、重新选主、落后节点追赶、失去多数派、全停后恢复。进程强杀不是硬件断电证明；安全承诺依赖文件系统/磁盘 fsync 契约，不涵盖磁盘丢失或多盘损坏。
